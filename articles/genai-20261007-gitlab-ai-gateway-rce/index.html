GitLab's AI Gateway Scored 9.9: Your Prompt Template Is Server-Side Code Now

On October 2, GitLab published a short advisory for a component most of its thirty million users have never seen: the AI Gateway, the service that brokers every Duo AI feature. The bug — CVE-2026-90970, CVSS 9.9 — let an authenticated user escape the prompt template sandbox through a crafted flow configuration and execute arbitrary commands on the gateway. Read that again: the prompt template. The thing we all treat as a blob of instructions for a language model turned out to be the attack surface.

I keep coming back to that phrase — prompt template sandbox. It quietly concedes something the industry has been dancing around for two years: somewhere along the way, prompt templates stopped being text and became server-rendered code, complete with the one thing code should never have in a template engine — an escape hatch a user can reach. This advisory is the first time I've seen that idea get a 9.9.

Every AI feature routes through one broker — and that broker holds the keys to all of them.

What the AI Gateway actually is

GitLab's AI features — Duo Chat, IDE code suggestions, merge request summaries, vulnerability explanations, and the newer Duo Agent Platform for autonomous flows — don't each talk to model providers on their own. They all route through a single service: the AI Gateway. It stores the prompt templates those features render, runs the flow pipelines agents execute through, and holds the organization-wide provider keys for whatever models you've wired up.

GitLab operates a hosted version of this gateway for GitLab.com, GitLab Dedicated, and Self-Managed instances using the managed path. But there's a second deployment mode: GitLab Duo Self-Hosted, where customers running air-gapped, regulated, or data-residency-constrained environments operate their own gateway instance on their own infrastructure. That's the population this advisory was really written for.

Scale matters here. GitLab's platform counts over 30 million registered users and is used by more than half the Fortune 100 — names like Nvidia, Lockheed Martin, Goldman Sachs, and Airbus. A command-execution bug in the service that holds every org's model credentials, sitting in the middle of every AI request, is not a niche event.

Anatomy of a 9.9

The published vector is CVSS:3.1/AV:N/AC:L/PR:L/UI:N/S:C/C:H/I:H/A:H. If you don't read CVSS fluently, here's the translation — and every field maps to something concrete about the bug:

A 9.9, field by field. The Scope Changed marker is the one that should worry you most.

  • AV:N — reachable over the network. It's a service; of course it's on the wire.
  • AC:L — low attack complexity. No race condition to win, no timing luck. A crafted flow configuration was enough.
  • PR:L — the part that stings. You don't need to be an admin. Any authenticated user with Duo Agent Platform access qualifies.
  • UI:N — nobody has to click anything. There's no phishing stage.
  • S:C — scope changed, the field that separates "data leak" from "sandbox failure." The attack crossed a security boundary the product itself drew: the prompt template was supposed to be isolated from the system rendering it. The isolation failed.
  • C:H / I:H / A:H — once you're on the gateway host, everything is on the table: the org-wide keys are readable, commands run as the gateway's service account, and the host can be taken down — which takes every AI feature in the organization down with it.

Why 9.9 and not 10.0? Only because of that PR:L — you need an account with Duo Agent Platform access. GitLab also hedged honestly: the escape worked "under certain conditions." Fair. But "under certain conditions, any user with agent access can run commands on the box that holds all your keys" is not the kind of conditions you negotiate with. GitLab credited invisiblemeerkat for the responsible disclosure — and notably, reached out to affected self-hosted customers privately before publishing anything.

The escape chain, step by step

GitLab classified the flaw as an improper neutralization issue in the custom flow prompt template. Strip the compliance language and here's what that means: the gateway renders user-configurable prompt templates through some template engine, and the engine's isolation — the sandbox that's supposed to let you template text without executing code — did not neutralize something a user could craft. The rendering step, which should have been pure text substitution, became code execution.

Four steps from a regular account to a shell on the broker — plus what that shell can reach.

The blast radius deserves its own sentence. Whoever lands on that host doesn't just get one feature's data. They get the organization-wide provider keys — steal them once and they can bill model calls against your account from anywhere. They sit in the path of every AI request, which in 2026 means a stream of source code, diffs, and prompts. They can switch the gateway off, and with it every Duo feature at once. And they're standing on a host that is, by definition, trusted inside your network — a lovely pivot point toward whatever else the gateway is allowed to reach.

One CVE, two very different customers

The most operationally interesting part of this advisory is who had to act. The fixed versions are 19.2.4, 19.3.2, and 19.4.1 of the AI Gateway itself — a separate version line from GitLab's main application, which tells you it's its own deployable service. Impacted versions ran the gamut: everything from 18.1.6 before 19.2.4, 19.3 before 19.3.2, and 19.4 before 19.4.1.

Same CVE, two customer classes — and the pager only rings on one side.

  • GitLab-hosted gateway customers: GitLab had already deployed the fix server-side before publishing anything. Their advisory states plainly that GitLab.com, Dedicated, and Self-Managed instances using the hosted gateway are protected and need to do nothing.
  • Self-hosted gateway customers (Duo Self-Hosted): "update immediately." Patch, restart, verify. They got targeted outreach before the public post, which is the right disclosure choreography — but the work, and the risk window, is theirs.

Notice who self-hosts AI gateways: exactly the organizations with the slowest change processes — air-gapped networks, regulated industries, jurisdictions with data-residency law. The deployment model built for maximum control is also the one that must sprint for every AI-infra CVE. That trade-off used to buy you distance from the internet. It doesn't buy you distance from the vulnerability feed anymore.

This didn't happen in a vacuum

Zoom out one month and the pattern is hard to miss. In September, GitLab patched CVE-2026-85706, a maximum-severity path traversal in Community and Enterprise Edition that let an unauthenticated attacker read credentials and secrets from vulnerable servers. Within a day, CISA added it to its actively-exploited catalog and gave federal agencies three days to patch under Binding Operational Directive 26-04. It was the fifth GitLab vulnerability tagged exploited-in-the-wild since November 2021, one of them used by ransomware gangs.

And the same week as the AI Gateway advisory, researchers reported PoeLLM malware — a cryptomining campaign that specifically hunts exposed AI servers. Different technique, entirely different target profile, same underlying reality: attackers have added AI infrastructure to their default scan lists. Your model gateway is now inventoried the way internet-facing Redis instances were five years ago.

Three incidents, one month, one lesson: the isolation layer around AI workloads is where attackers now look first.

Prompt templates are code — treat them like it

None of this is conceptually new; it's just wearing new clothes. Server-side template injection has been a celebrated bug class for a decade — template injection equals remote code execution is standing wisdom in application security, and mature template engines ship hardened sandboxes precisely because their escape routes keep getting found. When Apache Airflow fixed CVE-2024-37210 in 2024, the issue was a path traversal where connection and variable targets got resolved server-side during template rendering — dangerous for exactly the same reason: something user-influenced being processed inside a trusted rendering context.

What's new in the LLM era is the blast radius attached to templates. A prompt template used to interpolate a customer's name into an email. In an AI gateway, it interpolates your source code, your diffs, your agent tool calls — right next to a bucket of org-wide model credentials. The trust boundary around template rendering didn't move, but the value of what's behind it exploded. The industry re-priced the input; it hasn't finished re-pricing the renderer.

GitLab's fix — proper neutralization in three patched gateway versions — is the correct endpoint. But the general lesson is architectural: if users can author templates, you are running a code-execution service, whatever your marketing calls it. That has consequences:

  • Classify template authors like code committers. Who can define a custom flow is a deployment-critical permission now, not a convenience setting. In this incident it gated the entire chain.
  • Neutralize at render, not at review. Sandboxed engines, pinned versions, and an escape-corpus test suite in CI beat hoping reviewers catch clever syntax.
  • Shrink the credential blast radius. Org-wide eternal provider keys next to a template renderer is a design smell. Per-feature scoped, short-lived, rotate-on-read credentials make the next 9.9 boring.
  • Put the gateway host on a short leash. Egress filtering, audit logging, and minimal local privileges — assume the sandbox has an exit someone hasn't found yet.

The self-hoster's audit checklist

I run AI plumbing on my own hardware, so I read advisories like this one as a checklist against my own stack. If you self-host anything that renders prompts — a LiteLLM proxy, a gateway of your own, agent pipelines with user-editable prompts — this is the pass I'd run this week:

  • Inventory your AI gateways. Every service that stands between a user and a model API is now critical infrastructure. Name them, version them, put them in your patch tracker. If a component's version line surprises you, that's the finding.
  • Ask who can author a prompt template. Not who can use one — who can define one. If the answer is "any authenticated user," you have GitLab's pre-patch permission model.
  • Check the rendering engine's sandbox story. Is template rendering actually sandboxed? Which engine, which version, when did you last test it against a template-injection payload list?
  • Scope the keys behind the renderer. If compromising the renderer yields eternal org-wide keys, fix that before someone proves it matters. Scope per feature, expire aggressively.
  • Treat air-gapped as slow, not safe. The CVEs arrive by feed regardless. If you can't patch AI infra quickly, at least assume the version you're running is public knowledge — these things get flagged, enumerated, and exploited faster every quarter.
  • Don't roll your own template engine. The temptation in self-hosted setups is a home-grown mustache-style renderer in a scripting language. Every escape in this story happened inside a vendor's hardened sandbox. Yours will not do better.

The takeaway

The AI Gateway advisory is three paragraphs long and fixes itself into a routine patch. But it marks a line: this is the first time I've seen a prompt template sandbox escape assigned a near-maximum severity by a major vendor — the moment prompt infrastructure formally joined the threat model. The AI stack got a whole new class of load-bearing component, and it took exactly two years from "ChatGPT wrappers everywhere" to "your prompt renderer is a 9.9."

If you run GitLab with self-hosted Duo, the action is real and immediate: versions 19.2.4, 19.3.2, or 19.4.1, today, not this sprint. Everyone else building with agents: audit what renders your prompts and what that renderer can touch. The next advisory in this bug class will not be GitLab's.

A prompt template is server-side code with a friendly name. The sandbox is not a formality — it's the only thing between a user's clever syntax and your organization's keys.
