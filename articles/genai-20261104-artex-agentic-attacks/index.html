200 Organizations in 11 Days: Inside the ARTEX Agentic Attack Wave

November 4, 2026 · AI / Security / Agents · 9 min read

One framework, multiple operators, and a month that changed the threat model for everyone who runs agents.

I run an AI agent around the clock on a headless Linux server. It plans, executes, checks its own work, and reports back — the same controller-planner-worker pattern that shows up in every serious agent framework shipping today. Last week I read three security disclosures that described, almost feature for feature, that exact architecture. Except the operator wasn't drafting blog posts. It was forging administrator tokens and reading government mailboxes.

The framework is called ARTEX. According to Microsoft Threat Intelligence, a China-state-aligned actor used it to automate intrusions into hundreds of organizations. According to CrowdStrike, a single ARTEX controller ran simultaneous attacks against more than 200 organizations across 14 countries in 11 days. And this week the spillover hit services ordinary developers touch daily: Chainstack disclosed a production breach on November 3, and GitBook revoked every API token it had ever issued.

This isn't a story about a vulnerability you can patch on Thursday. It's about what happens when offensive security becomes an orchestration problem — and the people solving it are using the same tooling patterns the rest of us celebrate.

What ARTEX Actually Is

Strip away the threat-actor tradecraft and ARTEX is recognizable to anyone who has built with LangGraph or CrewAI. Microsoft describes it as a multi-agent LLM system written in Go with a Next.js frontend. It can use any AI model. It runs an autonomous penetration test from reconnaissance through data exfiltration with little human interaction. As the agents work, they accumulate discovered assets and vulnerabilities into a shared graph that every other agent can read — the same shared-memory pattern that makes modern agent frameworks useful.

Planner and worker agents over shared graph memory. If you've built agents, you've drawn this diagram.

The provenance is the part that should make every open-source maintainer think. ARTEX was developed by Chinese developers and released as an open-source project — a penetration testing suite, the kind of tool that gets starred on GitHub and demoed at conferences. Then it was used in real attacks against South Korean financial institutions, and its creators made it proprietary. Too late. CrowdStrike and Microsoft have now observed multiple distinct China-nexus groups running it, including Storm-0940 and a group CrowdStrike tracks as Vapor Panda.

That sequence — publish, abuse, retract, proliferate anyway — is now a documented lifecycle, not a thought experiment.

Three Campaigns, One Framework

The ConnectWise supply chain — Storm-0940

Microsoft ties ARTEX to the supply-chain compromise of ConnectWise's Cloud Backup application, disclosed in mid-October. With compromised application credentials in hand, the actor used ARTEX to attempt sign-ins to more than 2,250 Microsoft 365 tenants. The password spraying ran at more than 2,900 attempts per minute across over 300 accounts in eight organizations, and Microsoft captured more than 151,000 failed logon events. OAuth abuse isn't new for this actor — what's new is the pace. Microsoft flagged multiple intrusions where the time from initial targeting to privileged cloud access was under three hours.

Two hundred orgs in eleven days — Vapor Panda

CrowdStrike's report is the one I keep re-reading. Starting October 17, Vapor Panda used a single ARTEX controller against telecommunications providers, government ministries, and pharmaceutical, semiconductor, defense, and financial targets across 14 countries. The framework ran mostly on DeepSeek plus a second commercial LLM that CrowdStrike couldn't identify. Confirmed compromises at nine organizations ended with a BloodAlchemy backdoor installed; at least twelve more were password-sprayed.

The recovered transcripts read like any agent ops log. The operator issued instructions in Chinese and stepped in at decision points. When one attack path failed, the agents pivoted to another on their own. At one pharmaceutical firm, the agent combined an unsigned SAML assertion with an XXE flaw to reach the cloud metadata service, then climbed to an enterprise admin account. Against a Greek government entity, the operator supplied a 2022 directory export from the organization's own mail server — the authentication keys in it had likely never been rotated. The agent used them to forge an administrator token and read mailboxes, then found VPN configurations in a user's sent mail to push into the internal network. CrowdStrike also observed the operator instructing agents to skip every host running Falcon and work the unprotected ones.

One intrusion consumed roughly 1.4 billion input tokens. An agent team planning a single breach burned more tokens than most companies' entire monthly API bill.

The spillover: Chainstack, WorkOS, GitBook

While the espionage campaigns ran, the same wave reached downstream infrastructure vendors. Chainstack, a blockchain node provider, disclosed on November 3 that an attacker entered through a third-party component into a development environment on October 26, escalated into production, and accessed a database holding customer names, emails, and password hashes — plus systems holding node credentials, which the company is treating as exposed. The intrusion ran for five days before detection. WorkOS disclosed a smaller incident the same week, limited to go-to-market systems: CRM contacts, sales-call summaries, and excerpts of customer Slack conversations.

GitBook was hit hardest in developer-visible terms. Attackers accessed infrastructure credentials around 7 p.m. CET on November 2. GitBook suspended its application, revoked every API token, and warned that integration credentials, Git Sync secrets, and GitBook Assistant questions may have been exposed. PancakeSwap took its documentation offline entirely and then migrated off GitBook. For a documentation host whose customers publish API references and integration guides, "we rotated everything" is the only responsible ending — and even that cost them a marquee customer.

Machine speed, measured. Each of these numbers breaks a human-paced assumption in classical detection.

One more disclosure belongs in this section, because it's the most personal. The Dutch Institute for Vulnerability Disclosure — the folks who usually report other people's bugs — confirmed in November that the September attack on their own network was carried out by ARTEX acting autonomously. Initial access to root in 12 minutes, via a Zammad zero-day chained with a local privilege escalation flaw. While it worked, the agent read a compromised mailbox, scanned the internal network, extracted login tokens, and attempted password resets simultaneously. DIVD logged over 450,000 requests and 2,500 scripts and described the activity as "super loud and messy."

The Uncomfortable Mirror

Here's what I can't shake: nothing in ARTEX's architecture is exotic. Controller, planner agents, worker agents, shared graph memory, model-agnostic routing, human approval at decision points. I have run every one of those pieces — legitimately, on my own hardware, for this blog. The frameworks most of us use are architecturally indistinguishable from what breached a Greek government ministry. The differentiator isn't the stack. It's the objective handed to it.

CrowdStrike: the campaign "marks an escalation in China-nexus use of AI agents, from single intrusions to multiple simultaneous engagements directed by a human operator."

That sentence deserves a slow read. Multiple simultaneous engagements, one operator. The scaling law that made agents transformative for software work — one person directing many parallel workers — is now on the attacker's side of the ledger too. In September, "state actor with AI assistance" meant one intrusion with a chatbot in the loop. In November it means one operator running a 14-country campaign from a single console while another group hits 2,250 tenants in the same week.

Why Velocity Breaks Defenses

Security operations has always assumed a human pace on the other side: days of recon, patient credential testing, weeks between stages. ARTEX collapses those gaps. Under three hours from targeting to privileged access. Twelve minutes from first foothold to root. Credential spraying that would take a human operator weeks compressed into minutes — 151,000 failed logons is not a typo, it's a burst.

Microsoft: "Agents are not constrained by factors affecting humans — they can work around the clock, on weekends, and on holidays and attempt multiple breach paths simultaneously."

The counterweight, and it's a real one: agents are loud. DIVD's own phrase was "super loud and messy" — 450,000 requests, 2,500 scripts, parallel actions everywhere. A patient human red team makes almost no noise; an agent team makes a diffusion curve of noise. That means velocity itself is a detection signal. Auth systems that alert on failed-login rate rather than just failure, mailbox audits that flag mass token forgery attempts, and network monitors that flag parallel lateral movement can catch this class of attack — DIVD caught theirs in 12 minutes' worth of noise, after all. The organizations that got breached weren't out-alarmed; they were out-paced between alerts, or holding keys old enough to predate their detection rules.

The Tool-to-Weapon Pipeline

The lifecycle is documented now: publish, abuse, retract, proliferate anyway.

ARTEX's authors pulling the repo did nothing, because capable code doesn't un-exist. And the category is replicating. Kaspersky separately tracked CyberStrikeAI — another open-source Go pentest framework — running attacks on educational institutions in Africa and Latin America, with the LLM living on the attacker's command-and-control server and a dumb implant executing whatever commands the model drafted. The victims' machines carried no AI at all; the intelligence was rented from the other end.

This is the part of the AI security debate that moved from theory to invoice this month. We've spent two years arguing about whether models should be allowed to write exploits in sandboxed evaluations. Meanwhile, actual intrusion teams assembled commodity agent stacks from open-source components and off-the-shelf APIs, and ran them against governments and banks. The policy question didn't go away — it just got an answer nobody voted on.

What You Actually Do About It

None of this is abstract, and none of the mitigations are novel. They're hygiene items the campaign turned into evidence. Every item below maps to a documented failure from the disclosures:

Six moves, all mapped to real failures from this campaign.

  • Rotate stale credentials — a government ministry lost mailboxes because keys in a 2022 directory export still worked four years later
  • Treat every OAuth grant as supply chain — one compromised backup app reached 2,250+ tenants; audit what third-party apps can access and remove what you don't use
  • Alert on velocity, not just novelty — 2,900 spray attempts a minute and 450,000 requests in one attack are rate anomalies; make sure your auth path has rate-based alerting, not only signature rules
  • Rotate tokens when vendors disclose — GitBook revoked all tokens; Chainstack treated node credentials as exposed; treat any third-party breach notice touching you as a rotation event, same-day
  • Segment dev from prod — Chainstack's five-day intrusion started in a development environment; dev systems with prod credentials are the soft entry point
  • Assume EDR-aware agents — operators explicitly excluded Falcon-protected hosts; your unprotected machines are not low-value, they're just the ones the agent was pointed at

And if you build agent software — which, if you read this blog, you probably do — the pipeline diagram above is a live ethical question, not a threat-intel curiosity. The gap between "autonomous pentest agent" and "autonomous breach agent" is one system prompt wide. Capability gating, deployment guardrails, and honest threat modeling of your own tool are becoming part of the job, the same way SQL injection awareness became part of ours fifteen years ago.

Where I Come Down

The ARTEX story is not a warning about AI someday being dangerous. It's a report on AI already being useful — in the service of people we'd prefer it wasn't. The same scaling laws, the same orchestration patterns, the same multi-model routing that make agents the most productive developer tool of the decade make them a force multiplier for intrusion teams. The architecture is neutral; the operator is not.

So I did the boring thing this week. Rotated every credential on my own server that predates this year, audited the OAuth grants on my primary accounts, and added rate-based alerts to the auth paths I control. Twenty minutes of hygiene against a threat that operates in minutes. The agents aren't going back in the box — on either side of the keyboard. The only open question is whether your credentials, your tokens, and your detection rules are ready for an adversary who never sleeps, never gets bored, and reads your old email exports.
